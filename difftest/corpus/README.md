# Corpus

`*.les`: 実行コード、`*.stdin`: 標準入力（任意）、`*.expect.json`: 正確な stdout / stderr / exit_code の期待値。

初期ケースは upstream の Go 実装・Go テストから選んだ **未実行の候補**です。P0 の `run.py` で実際に照合し、不一致があれば期待値を勝手に追認しないで原因を記録してください。今後はケースごとに規則 ID を付けていきます。

## stderr の照合
`run.py` は stderr 中のケースファイルの絶対パスを `<CASE>` に置換してから期待値と比較する。エラー系ケースは `stderr` を期待値に書いて厳密に比較する（exit code が合うだけでは PASS にならない）。

### 追加分（E2・E11〜E13・E17・E22）

各ケースは「別の評価戦略なら出力が変わる」ように作った。表の「区別する対象」は、その戦略だとどう変わるか。

| ケース | 規則 ID | 台帳 | 区別する対象（期待 stdout） |
|---|---|---|---|
| `order-binary-operands` | E17 | ORD-001 | `print a() + b()`（`a` / `b` が印字する）: 左から右なら `a;b;3`、右から左なら `b;a;3` |
| `order-print-args` | E17, E19 | ORD-001 | `print a(), b()`: 全引数を強制してから書き出すので `a;b;12`。引数ごとに書き出す実装なら `a;1b;2`、右から左なら `b;a;21` |
| `order-binary-abort` | E17, E21 | ORD-001 | 左（`a`）が失敗すると右（`b`）は評価されない: stdout `a;`、`:3:` col 5（関数内の文頭）。右から左なら `b;a;` |
| `live-global-in-function` | E13 | FN-001 | 関数本体は定義後に再束縛されたグローバルを見る: `3;4`。定義時のスナップショットなら `3;3` |
| `ident-arg-not-forced` | E11 | FN-001 | 識別子の引数は呼び出し時に強制されない（`n = 1 / 0`、`k(n)` で `k` は引数を使わない）: `1`。引数を即評価する実装ならエラー |
| `ident-arg-shares-cell` | E11 | FN-001 | 識別子の引数は呼び出し側の束縛と同じ Cell: 呼び先で強制した結果が共有され `side;21`。コピーなら副作用が 2 回、名前渡しなら呼び先の中で 2 回 |
| `call-local-rebind` | E12 | FN-001 | 関数内の `x = 2` は局所束縛: `2;1`。グローバルに書き込む実装なら `2;2` |
| `call-body-last-value` | E12 | FN-001 | 本体の文は順に全部実行され、値は最後の式文: `a;b;3` |
| `alias-binding-not-forced` | E1, E2 | LZ-001, LZ-006 | `m = n`（`n = 1 / 0`）は `n` を強制しない: `ok`。**E1 と E2 を分けては示せない**（設計メモ 2.1 節末の注） |
| `ident-stmt-forces` | E22 | LZ-006 | 識別子だけの文は変数を強制する: `n = 1 / 0`⏎`n` でエラー（`:1:` col 7）。強制しない実装なら `ok` |
| `ident-stmt-calls-function` | E22 | LZ-006 | 識別子だけの文が `def` なら 0 引数で呼び出す: `hi;end`。呼ばない実装なら `end` |

### 追加分（P1c-6: closure の親スコープ・引数 Thunk の環境捕捉）

| ケース | 規則 ID | 台帳 | 区別する対象（期待 stdout） |
|---|---|---|---|
| `closure-defining-scope` | E12, E13 | FN-001 | `y = 3`、`def f(): y`、`def g(): y = 99; f()`: `f` の親は**定義時のスコープ**なので `3`。呼び出し元（`g` の子スコープ）を親にすると `99` |
| `arg-thunk-snapshot-env` | E11, E14 | LZ-005, FN-001 | `a = 1`、`def f(p): p`、`b = f(a + 1)`、`a = 10`、`print b`: 引数 Thunk は `b` の Thunk の `snap`（`a` = 古い束縛）から捕捉するので `2`。生きたスコープだけを見ると `11` |

**観測上の限界（`arg-thunk-snapshot-env`）**: このケースは「`snap` を見ず生きたスコープだけを引く」実装は区別するが、「引数 Thunk を `capture` し直す」実装と「`suspended a env` のまま使う」実装は**区別しない**（どちらも `2`）。区別できる例は見つかっていない。

**観測上の限界**: E2（式としての変数参照は強制しない）と E12 の「未評価の戻り値」は、9 ノードの範囲では独立に実証できない。遅延位置では E1・E11 が同じ結果を与え、強い位置では消費側が強制し、識別子だけの文は E22 で強制するため。E2 を独立した規則として実証したとは主張していない。

既存 10 件（`basic-print` など）の規則 ID は `tasks/results/P1c-3.md` に対応表がある。
