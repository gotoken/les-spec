## 個別テスト（`unitTests`、AST を直接組む。18+2 件、すべて PASS）

- 共有・メモ化: 副作用つき Thunk は 3 回要求しても 1 回だけ実行され、Cell は `done` に上書きされる。Go CLI でも同じ（`x = print "s;"`、`x` を 3 回 → `s;` が 1 回）。同じ束縛を 2 つの引数に渡すと `33`（Go も `33`）。
- 遅延: 強制されない束縛は `suspended` のまま。
- ブラックホール: 位置なしの error、直前の出力は残る、Cell は `blackhole` のまま。
- 再束縛で古い Cell が残る: `a=1; b=a+1; a=10` の後、`b` のスナップショットの `a` は新しい束縛とは別アドレスの `done 1`。再束縛の右辺は即時評価（col 7）。
- 強制順: 二項演算の両オペランド・`print` の引数がともに失敗するとき左のエラーが報告される。
- fuel: 0 や深い式に対する小さい fuel は OUT_OF_FUEL（観測として扱わない）、十分な fuel では確定する。
- 未対応: `def` は後続の文を実行せずに UNSUPPORTED。
- 位置: 内側の強制式（col 14）が優先される。

ミューテーション確認（評価器を一時的に壊して失敗することを確認し、元に戻した）: メモ化なし → 4 件 FAIL、スナップショットなし → 3 件 FAIL、再束縛を遅延にする → 3 件 FAIL、二項演算を右から先に強制 → コーパスは 0 件 FAIL（段階 A の 19 件には強制順を区別する例が無い）だが、個別テストが 1 件 FAIL。強制順の最小例は `def` を使うコーパス（order-*）に限られるため、段階 B で強制順をコーパスでも検証する。
