## 証明した命題（対象は既存の `capture` / `lookupEnv` / `Heap.lookup` / `Heap.bind`）

`env.scope < heap'.scopes.size` は「対象スコープが存在する」ことの明示的な仮定。

| 依頼 | 定理 | 仮定 | 内容 |
|---|---|---|---|
| 1 | `capture_unbound_lookup` | `lookupEnv m.heap env n = none`（作成時に未束縛）、`capture` が成功 | 生成された `env'` で、`env'.snap.find? (·.1 == n) = none`（P2c-1 の `capture_unbound` から導出）、`env'.scope = env.scope`、`lookupEnv heap' env' n = heap'.lookup env.scope n`（任意の Heap）。式に `n` が現れるかどうかは問わない |
| 2 | `forward_ref_resolves` | 上 + `env.scope < heap'.scopes.size` | `lookupEnv (heap'.bind env.scope n a) env' n = some a` |
| 3 | `forward_ref_rebound` | 上と同じ | さらに `n` を `b` に再束縛すると `lookupEnv (…) env' n = some b`（最新） |
| 4 | `Heap.lookup_local_priority` / `Heap.lookup_of_lookupLocal` | ローカルに `lookupLocal s n = some a` | `lookup s n = some a`。親スコープの同名束縛（`lookup p n = some a'`）があってもローカルが優先 |
| 補助 | `Heap.lookup_bind_self` / `Heap.lookup_rebind` | `s < h.scopes.size` | `bind` 直後（再束縛を含む）に `lookup s n` は最新の束縛を返す。P2a の `Heap.bind_lookupLocal_self` と `Heap.bind_scopes_size` を再利用 |
| 区別 | `forward_ref_cell` | `heap'.ValidAddr a` | 「名前が解決できる」（アドレスが返る）ことと「そのアドレスが有効な Cell を指す」ことは別。束縛するアドレスが有効なら `bind` 後も有効で、Cell は `bind` では変わらない（`Heap.bind_validAddr` / `Heap.bind_cell?`）。解決できるだけでは有効性は導けない |

## 仮定として残したもの・未証明の性質

- **親スコープの循環・不正な参照を含む Heap 全体の整合性**は証明も仮定もしていない。`Heap.lookup` は fuel（`scopes.size + 1`）で打ち切るため循環があっても停止するが、ローカルに無い名前を親へたどる場合の「親の `lookup` と同じ結果になる」ことは **fuel が 1 つずれるため示していない**（ローカルに束縛がある場合だけ扱った）。
- 束縛先のスコープが存在しない場合 `Heap.bind` は何もしない（定義）。定理 2・3 は存在を仮定している。存在しなければ前方参照は解決されない（`lookup` の結果は束縛前と同じ）が、これは定理にしていない。
- 作成時に**束縛されていた**名前の保存性は P2c-1。`whnf` が値を返すまでの評価器全体の正しさ（前方参照した Cell を強制した時に最新の値が得られること）は対象外。
- `lookupEnv` が返すアドレスが有効な Cell を指すこと（`Heap` の整合性）は `forward_ref_cell` の条件付き形のみ。
