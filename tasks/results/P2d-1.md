## 整合性の定義（`Heap.StructWF` は構造的な 3 条件だけで、完全な整合性ではない）

| 述語 | 内容 |
|---|---|
| `Heap.VarsValid` | 1. `Scope.vars` のどのアドレスも `cells` の範囲内（`ValidAddr`） |
| `Heap.ParentsValid` | 2. `Scope.parent = some p` なら `p < scopes.size` |
| `Heap.ParentsDecreasing` | 3. `Scope.parent = some p` なら `p < s`（親は添字が小さい）。**循環しないための十分条件**であって必要十分ではない（`Heap.newScope` が親を先に作る使い方に対応） |
| `Heap.StructWF` | 上の 3 つの連言 |

**含まないもの**（今回の対象外）: `Cell.suspended` の `Env.snap` / `Env.scope`、`Cell.blackhole`、`Value.closure` の捕捉スコープが指す参照の有効性、Cell の内容に関する不変条件、`demand` / `evalE` / `exec` を通した保存。

## 保存性（仮定を明示）

| 定理 | 仮定 | 結論 |
|---|---|---|
| `Heap.initial_structWF` | なし（`Heap.initial_eq : Heap.initial = {…} := rfl` で具体値を出して検証） | `Heap.initial.StructWF` |
| `Heap.alloc_structWF` | `h.StructWF` | `(h.alloc c).1.StructWF`（Scope は不変、Cell は増えるだけ。P2a の `alloc_scopes` / `alloc_validAddr`） |
| `Heap.setCell_structWF` | `h.StructWF` | `(h.setCell a c).StructWF`（Scope・Cell の個数は不変。P2a の `setCell_scopes` / `setCell_validAddr`）。**`StructWF` は Cell の内容を含まないので、Cell 内の参照（`Env.snap`・`closure` のスコープ）まで整合性に含める場合は、書き込む Cell の参照が有効という別の仮定が要る** |
| `Heap.newScope_structWF` | `h.StructWF`、`∀ p, parent = some p → p < h.scopes.size` | `(h.newScope parent).1.StructWF`（新スコープの添字は古い `scopes.size`、親はそれより小さい、`vars` は空） |
| `Heap.bind_structWF` | `h.StructWF`、**`h.ValidAddr a`**（束縛するアドレスが有効） | `(h.bind s n a).StructWF`。束縛先スコープが存在しなければ `bind` は何もしないので、スコープの有効性の仮定は要らない |

## 反例

- `bind_invalid_breaks_varsValid`: 初期 Heap のスコープ 1 に存在しないアドレス 99 を `bind` すると `VarsValid` が壊れる（`bind_structWF` の `ValidAddr a` が必要な理由）。
- `selfParent_valid_not_decreasing`: スコープ 0 の親がスコープ 0 という自己参照は `ParentsValid` を満たすが `ParentsDecreasing` を満たさない。`Heap.lookup` は fuel（`scopes.size + 1`）で打ち切るので停止はするが、循環が無いことの保証は `ParentsDecreasing` のような別の条件が要る。

## 未証明の参照関係

- `Cell` の中の参照（`Env.snap` の各アドレスが有効、`Env.scope` が存在する、`Value.closure` のスコープが存在する）の整合性と、その保存。
- `ParentsDecreasing` が `lookup` の結果と fuel の関係（親へたどった `lookup` の等式）をどう簡単にするか。

- `StructWF` が評価器の実行中に（`bind` や `alloc` 以外の経路で）壊れないこと。
