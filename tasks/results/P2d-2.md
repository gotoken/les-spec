# P2d-2: Cell 数の単調性のための基本補題

ブランチ `p2d2-monotone`、ファイル `lean/Les/Proofs/Monotone.lean`（`Les.lean` から import）。
既存の評価器・Heap・過去の証明ファイルは変更していない。`sorry` / `admit` / 新公理 / `partial` / `unsafe` なし。
`#print axioms`: `mono_bind`・`mono_tryCatch` は `propext` のみ、`mono_validAddr` は公理なし。

## 定義
- `Machine.CellsMono m m' := m.heap.cells.size ≤ m'.heap.cells.size`（`refl` / `trans` 付き）。
- `Mono x := ∀ m, m.CellsMono ((x.run).run m).2`。`x : EvalM α` の最終状態だけを見る定義なので、成功でも例外でも同じ主張になる
  （`ExceptT Halt (StateM Machine)` では例外までの状態変更が残る）。

## 命題
| # | 命題 | 補題 | 仮定 |
|---|---|---|---|
| 2 | `alloc` は Cell 数を 1 増やす | `Heap.alloc_size`（等式）、`alloc_cells_size`（EvalM 版の等式）、`mono_alloc` | なし |
| 3 | `setCell` / `bind` / `newScope` は Cell 数を変えない | 既存 `Heap.setCell_size` / `Heap.bind_cells`、新規 `Heap.newScope_cells(_size)` | なし |
| 4 | 基本操作の単調性 | `mono_pure` `mono_throw` `mono_getHeap` `mono_alloc` `mono_modHeap_setCell` `mono_modHeap_bind` `mono_modify_stdout` `mono_newScope`（`callClosure` の `modifyGet`） | なし |
| 4 | `modHeap f` | `mono_modHeap` | `∀ h, h.cells.size ≤ (f h).cells.size` |
| 5 | `bind` の合成 | `mono_bind` | `Mono x` かつ `∀ a, Mono (f a)`。`x` が例外で終わるときは `f` が走らず、`x` までの状態がそのまま最終状態 |
| 5 | `tryCatch` の合成 | `mono_tryCatch`（評価器の `tryCatch … (throw (h.attach p))` 用に `mono_rethrow_attach`） | `Mono x`、`∀ e, Mono (handler e)` |
| 6 | 有効アドレスの保存 | `Machine.CellsMono.validAddr`、`mono_validAddr`（成功・例外の両方）、使用例 `example_validAddr_preserved` | `Mono x`、開始時に `ValidAddr a` |

使用例 `mono_example_alloc_bind_throw` は `alloc → bind → throw` の列を `mono_bind` だけで組み、例外で終わる経路も含めて示す。

## 反例（成り立たない一般命題）
- `modHeap_not_mono : ¬ (∀ f, Mono (modHeap f))`。`f := fun h => {h with cells := #[]}` で Cell 数が 1 → 0 になる。
  よって `modHeap` の単調性には引数関数への仮定が必要。

## 扱っていないもの
`demand` / `evalE` / `whnf` / `execCore` の再帰全体の単調性（次の工程でこの補題を組み合わせる）。
`mono_modHeap` の仮定は評価器の呼び出し（`setCell` / `bind`）では上の具体補題で満たされる。
