# P2d-3: 評価器の Cell 数単調性

ブランチ `p2d3-monotone-eval`、ファイル `lean/Les/Proofs/MonotoneEval.lean`（`Les.lean` から import）。
既存の評価器・Heap・`Mono` の定義・過去の証明は変更していない。`sorry` / `admit` / 新公理 / `partial` / `unsafe` なし。
`#print axioms demand_mono`: `propext`, `Quot.sound` のみ。

## 最終目標（達成）
```
theorem demand_mono (fuel : Nat) (e : Expr) (env : Env) : Mono (demand fuel e env)
```
`Mono`（P2d-2）は最終状態の Cell 数だけを見るので、`ok` / `error` / `exit` / `unsupported` / `outOfFuel` のすべての終了を含む。
仮定として置いた未証明の単調性はない（条件付き定理ではない）。

## 証明構造（循環なし）
`MonoAt n`: fuel `n` での 11 関数
`evalE, whnf, demand, callBuiltin, callClosure, prepArgs, prepArg, forceAll, execBlock, exec, execCore`
の単調性の連言。`monoAt_zero`（全関数が `throw outOfFuel`）と `monoAt_succ`（`MonoAt n → MonoAt (n+1)`）を `monoAt n` の帰納法で結ぶ。
fuel `n+1` の各関数は fuel `n` の関数だけを呼ぶので、`monoAt_succ` は帰納法の仮定だけを使う。

再帰的な依存（fuel `n+1` → fuel `n`）:
- `evalE` → `demand`, `prepArgs`, `callBuiltin`, `callClosure`
- `whnf` → `demand`（`setCell blackhole` → `demand` → `setCell done`。各 `modHeap` は P2d-2 の `mono_modHeap_setCell`）
- `demand` → `evalE`, `whnf`（`tryCatch` は `mono_tryCatch`、ハンドラは `throw` の付け替え）
- `callBuiltin` → `forceAll`, `whnf`
- `callClosure` → `execBlock`（局所再帰 `bindParams` は fuel 不使用なので別補題）
- `prepArgs` → `prepArg`; `prepArg` → `evalE`; `forceAll` → `whnf`
- `execBlock` → `exec`（`foldlM`）; `exec` → `execCore`; `execCore` → `evalE`, `whnf`, `demand`, `callClosure`

## 補助補題
- 非再帰: `mono_primErr`, `mono_capture`, `mono_arith`, `mono_showValue`（P2d-2 の `mono_pure` / `mono_throw` / `mono_getHeap` / `mono_alloc` / `mono_modHeap_*` / `mono_newScope` / `mono_modify_stdout` を再利用）。
- 繰り返し: `mono_foldlM`, `mono_mapM`, `mono_forM`, `mono_bindParams`（仮引数リストの構造再帰）。
- 系: `evalE_mono`, `whnf_mono`, `execBlock_mono`, `exec_mono`, `demand_validAddr`（`demand` 開始時に有効なアドレスは、例外終了でも終了時に有効）。

## 未証明・やらないこと
- P2b-2 の `whnf_suspended_ok_cell` の `hvalid` 仮定の除去はしていない（`demand_validAddr` はその部品だが、適用は次の工程）。
- 単調性以外（Cell の中身・Scope・stdout など）は扱わない。`execAll` / `run` の単調性は未証明（`mono_forM` と `exec_mono` から続けて導ける）。

## 証明の道具
fuel に関する帰納法、`unfold`、`cases`、`split`、独自マクロ `mono_tac`（`repeat'` で `mono_bind` / `mono_tryCatch` / `mono_mapM` / `mono_foldlM` を適用し、葉は `with_reducible exact` で既知の補題か帰納法の仮定で閉じる）。
`monoAt_succ` は 11 関数の展開が重く、`set_option maxHeartbeats 2000000` をこの 1 定理にだけ付けた（ビルドは約 45 秒）。

## 試行回数・モデル
コンパイル失敗は 6 回。意味論の曖昧さや戦略の迷いはなく、すべて自動化の調整だった:
1) `mono_arith` の `exact` が型の大きい目標で timeout、`bindParams` の射影の型不明。
2) マクロ前の docstring 構文、`bindParams` の暗黙引数。
3) `intro` が `Mono`（def）を展開して `Machine` を導入してしまう → 葉の後ろに回した。
4) `isDefEq` の timeout（`exact` が bind の目標を展開）。
5) `with_reducible exact` に変更。`rw [f]` が equation theorem を使えない関数があり `unfold` に変更、重なりパターンは `cases` を先に。
6) `execCore` が 200000 heartbeats を超えた → `maxHeartbeats` を上げて成功。
2〜6 は同じマクロの調整だが、毎回別の原因で、未解決のまま 3 回に達した問題はない。Sonnet 5.5 のみ。`semantics-opus` は 0 回。
